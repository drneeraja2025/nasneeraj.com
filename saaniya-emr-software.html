The data boundary

One boundary decides everything

Most clinic software asks you to upload your patients' medical history to someone else's servers. Saaniya EMR draws a hard line instead.

Stays on your clinic hardware

  • Diagnoses and assessment notes
  • Examination findings and specialty chart fields (when used)
  • Prescriptions, dosages, and instructions
  • Vitals, uploaded reports, and scans
  • Invoice line items describing treatment

Syncs only to run online booking

  • Patient name and phone number for the appointment
  • Requested date, time, and appointment status
  • Your clinic's configuration and branding
  • Licence and subscription state

Booking contacts are still personal data, so they are covered by a Data Processing Agreement, encrypted in transit, and kept for a short window only. What we never receive is the clinical record itself.

Under the hood

How it is built.

Written down here because clinics increasingly ask, and because a vague answer about security is usually a bad one.

Desktop shell

Tauri 2 with a React interface — a small signed Windows installer rather than a browser bundled into an application.

Storage

SQLite encrypted with SQLCipher using AES-256, with an Argon2id-derived key and the session key held in the operating system keychain.

Optional chart packs

Extra specialty fields are validated JSON Schemas in a registry — not separate products. Forms render from the schema, so the payload stays structured, queryable, and exportable.

Sync

An outbox with idempotency keys and cursor-based pulls. Offline is the default assumption, and only allowlisted booking fields ever move.

Installer and pilot onboarding details are shared when you enquire. This website collects no patient or clinical data of any kind.
